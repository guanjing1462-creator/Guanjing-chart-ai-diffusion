# 超越 Mug-Diffusion 的架构设计（第 126 轮）

## 一、Mug 做了什么（从源码读出来的）
| 部件 | 实现 |
|---|---|
| 表示 | 谱面 → 钢琴卷张量（`x_channels = 4键 × 4`），经 VAE 压到 latent（z=16, 长度 512） |
| 第一阶段 | `AutoencoderKL`（复用了 Stable Diffusion 的 VAE 结构） |
| 第二阶段 | `UNetModel` 扩散：in=16, model_channels=128, channel_mult=[1,2,3,4], attention=[8,4,2] |
| 条件 | ① 音频 mel 频谱（`audio_channels=[256,512,512,512]` 注入 UNet）② 类别特征嵌入（难度/风格/LN 比例/模式） |
| 训练 | DDPM 1000 步，eps 参数化，smooth_l1，lr 1e-5 |
| 推理 | 噪声 → 去噪 → VAE 解码 → 转换器 → .mc/.osu |

**它的强项**：音频条件 + 端到端生成 + 难度/风格可控。
**它的弱点（可超越的地方）**：
1. **固定长度的 latent**（z_length=512）→ 长曲要靠拼接，段落结构弱；
2. **纯音频条件**，没有显式建模「段落重复/动机复用」——人类谱大量使用重复段落；
3. **类别条件太粗**（难度只是一个嵌入），没有「目标难度数值」的连续条件；
4. 没有把**键型统计**（npr/jack/1/32/手位移）作为可控旋钮。

## 二、我们的目标架构（分三层）
```
音频 → onset/频带特征 ─┐
                        ├→ 条件融合 → 扩散主干（长上下文） → 钢琴卷 → 网格对齐 → .osu
风格/难度数值/键型目标 ─┘
```

### 1. 表示层（超越点：变长 + 段落感知）
- 窗口 128 行（8 小节），但**训练时同时学习窗口边界条件**（前一窗口的最后 16 行作为条件）；
- 推理时按小节拼接，用重叠窗口平滑过渡，避免拼接痕迹。

### 2. 条件层（超越点：连续难度 + 键型目标）
- **连续难度标量** d∈[0,1]（映射到 Koishi 难度 10-20 区间），用 Fourier 特征编码，而不是离散嵌入；
- **键型目标向量** t∈R⁴（npr、jack 率、1/32 占比、手位移），用 MLP 编码后加到时间步嵌入上；
- 音频特征：每格 4 维（低/中/高/总 onset），窗口内 128×4，用小型卷积编码器压成 128×64 后与 UNet 通道拼接。

### 3. 主干层（超越点：长上下文）
- CPU 限制下先用一维 U-Net（现在这个）；
- 有 GPU 后换 **Transformer 主干**（窗口内 512 token + 跨窗口记忆），或 **DiT**。

## 三、训练配方（分阶段）
| 阶段 | 数据 | 目标 |
|---|---|---|
| A 无条件预训练 | 全部 30551 窗口 | 学会「像人写的谱面」（现在这一步） |
| B 风格/难度条件 | 同上 + 标签 | 可控生成 |
| C 音频条件 | 6 首歌的窗口子集 | 接口验证（数据太少，只做可行性） |
| D 键型微调 | 按 Koishi 概率向量做奖励 | RL/DPO 式对齐到目标键型 |

## 四、评估标准（沿用第 123 轮的方法）
- **不再看单标签**（人类自己只有 42-45% 一致）；
- 用 **5 维键型概率向量与目标包质心的余弦相似度**，基准：jack 0.95 / stamina 0.71 / tech 0.66 / speed 0.61；
- 难度用 Koishi `numericDifficulty` 与目标曲线比对；
- 附加：占位率、npr、1/32、卡手检查。

## 五、CPU 现实约束
- 训练一个 epoch（30551 窗口）在 8 核 CPU 上要 10 分钟以上 → 必须缩小模型/数据；
- 当前用 base=32-48、128 行窗口、200 步扩散，参数量 0.2-0.4M；
- **真正的 Mug 级模型（128 通道 U-Net + VAE + mel 条件）需要 GPU**，
  这里的产物是「可验证的完整训练管线 + 小规模可用模型」，不是同等规模的大模型。
