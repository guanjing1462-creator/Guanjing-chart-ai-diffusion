`tools/diff-data32-grouped.py` / `tools/diff-data32-spotcheck.py` / `tools/diff-data32-overlap-audit.py`

## 0. 结论

- 新数据集 **95574 个窗口** 落在 1/32 网格（`[4,256]`），每个窗口带 `chart_id / group_id / split /

- 旧 `out/diff-data32/dataset.npz`（88787 窗）没有 `chart_id/group_id/split/start_cell`，
  **任何验证数字都不能证明无同曲/重叠窗泄漏**；本数据集可逐窗复现来源。

## 2. 构建口径

- **网格**：`cell(t) = round(8 * beat(t))`，`beat(t)` 由 manifest 的 `timing_segments`
  （只含 `[TimingPoints]` 段、只认 `uninherited=1` 的红线）分段给出；1 格 = 1/32 音符 = 1/8 拍。
  逐窗**不再**把首音符归零，窗口起点对齐全局网格 `k*128`，因此同一谱内所有窗口相位恒定。
- **窗口**：`[4, 256]` 格 = 32 拍 = 8 小节 4/4；滑窗步长 **128 格**（50% 重叠）。
  旧工具用 64「行」（音符行，不是格），相位随窗口首音符漂移、重叠量随音符密度变化。
- **划分**：完全继承 manifest 的 `chart.split`，窗口不做任何随机划分；同组/同谱窗口必然同 split。
- **难度标签**：`diff` = 行率 RPS 4 档（阈值 8/12/16，与旧 `diff` 同阈值，但旧文档把它写成
  nps，本次改名并另给 `diff_nps` = 音符头率 NPS 4 档，阈值 16/20/24）。
- **跳过**：候选 99184 窗 → 保留 95574，丢弃 3610 个占用格 <20 的空窗；2571 张谱全部参与，无跳谱。

### 3.3 窗口重叠（用 `start_cell` 与窗口长精确判断）

区间：`[t(start_cell), t(start_cell+256))` 毫秒；严格口径直接比较，保守口径两端各外扩半格
（吸收 `round()` 最大量化误差 ≈10~22ms）。

| 口径 | 同组跨 split | 同组同 split | 同 chart 相邻窗口 |
|---|---:|---:|---:|
| 严格 | **0** | 41 440 671 | 92 340 |
| 保守（±半格） | **0** | 41 644 202 | 181 766 |

**关于「任何两个不同来源窗口重叠必须为 0」这一条，做不到字面意义上的全局 0，如实说明：**

- **跨 split 的不同来源窗口：0 对**（同源组内、两种口径都验证）。这是泄漏相关的那一类重叠，
  已为 0。
- **同 split 内仍重叠，但都不产生跨集泄漏**：
  1. 同一张谱的相邻窗口按设计重叠 128/256 格（92 340 对）——这是滑窗 50% 重叠，训练时本来就这样用；
  2. 同一个同源组内不同谱的窗口在（换算后的）音频时间上重叠 41.4M 对。这些组多是
     「练习包共 set ID」的保守合组：组内往往是**不同歌曲的不同难度谱**，各谱时间原点都在自己
     首红线附近，所以这种重叠大部分是坐标巧合而非同一音频的真实重叠；它们全部落在**同一
     split**，对验证数字没有污染。
- **跨组**：格坐标相交 4 189 955 108 对，但不同组各谱的 `cell 0` 在各自首红线，**格坐标不可
  当作同一时间轴**，因此不给「重叠时长」断言。跨组是否真为不同曲，本次无法证明（见 §7.2）。

## 6. 修掉的解析问题

1. **网格不再猜**：旧脚本以相邻行间隔中位数（40~400ms）估 1/16 再折半；现在只读
   `[TimingPoints]` 且只要 `uninherited=1` 的红线 `beatLength`。旧估计的相对误差：中位
   0.55%，**p90 高达 99%**（约一成的谱步长差近一倍）；量化残差中位从 0.25 格降到 0.0167 格。
2. **timing 只从 TimingPoints 段取**：旧 `diff-data32.py` 扫全文件取行，`[HitObjects]` 等行会被
   误当 timing（manifest 实测 `legacy_timing_first_candidate_outside_timingpoints=378`）。
3. **变速谱按分段红线处理，不跳谱**：269 张 `tempo_changes` 谱、16928 个窗口；
   `cell(t)` 用窗口所在红线段换算，`bpm` 标签也是局部 BPM。
4. **绝对格坐标**：`start_cell` 是该谱固定原点上的坐标，不再逐窗归零 → 窗口相位恒定，
   不再需要旧脚本的 `off_parity`（按窗口内多数奇偶性归一）补救。
5. **步长改为格（128）而不是行（64）**：重叠量确定（50%），窗口数不再随音符密度漂移。
6. **来源可追溯 + split 继承**：每个窗口能回指 `chart_id` → 源 `.osu`（抽查逐位复现）。
7. **难度标签改名**：旧 `diff` 实际按 RPS 分档却写成 nps；现在 `diff`(RPS) 与 `diff_nps`(NPS) 分开。
8. **首红线之前的音符不丢**：208 张谱有负格音符，允许负 `start_cell`（219 个窗口），不因此剔谱。
9. **沿用 manifest 的严格解析断言**：重新解析 2571 张谱的玩法哈希与 manifest 逐一相等（校验通过），
   不存在「两套 .osu 语义」的隐性分歧。

## 7. 剩余限制

1. **LN 只有头部**：与旧数据一致，`type&128` 的起点进卷，`hold/release` 未入卷；跨窗 LN 无
   carry-in/carry-out。影响模型对 LN 时值的建模，不影响来源与泄漏断言。
2. **没有音频，无法证明跨组不同曲**：2601 个接收文件的 `audio_file_unavailable`，`audio_sha256`
   全为 null；组身份靠 set ID / 标题+艺人 / 音频引用名。改名、转码、不同音频文件同曲仍可能被分到
   不同组——这是**本次无法消除的泄漏上界**，报告不声称「绝对无同曲」。
3. **非 1/32 内容被量化**：14.61% 的音符偏离 1/32 格 >0.25 格（1/48 三连音、1/64 等），838 张谱
   的非格点内容超过 10%。这些内容被吸到格点上，使格口径 p132（0.2637）**高于**毫秒口径（0.2545），
   不能把格口径当作「人类真实 1/32 占比」；要报该指标请用毫秒口径或按谱加权。
4. **组粒度过粗**：练习包共 set ID 被保守合组，最大组 864 谱/32513 窗全在 train；按窗口均匀采样
   训练会让「同一批包」反复出现，val/test 各只有 17 组、5k/3.5k 窗口，指标方差大。
5. **同谱窗口仍 50% 重叠**（同 split）：训练可接受，但别用 val 里同谱相邻窗口当「独立样本」做统计检验。
6. **半格内容 23.4%**：模型必须真的输出 1/32 才能匹配；旧 1/16 模型结构上做不到。
7. 本次未训练、未评估（约定不跑 torch），因此没有任何「效果更好」的结论，只有数据侧保证。

## 10. 对下一次训练的建议

用 `diff_nps` 做难度条件、按 `group_id` 做组均衡（或对最大组设上限）采样，并让 val/test 同时报
「池化」与「组均」两套指标——否则 864 谱的最大组会主导训练与验证数字。
