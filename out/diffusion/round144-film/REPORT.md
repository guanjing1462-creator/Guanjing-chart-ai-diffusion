# 第 144 轮：把风格条件换成 FiLM —— 结论是**不够**，需要按风格分模型

**范围**：只训练 + 统计 + 采样验收。不出谱包、不碰 `tools/paint-gj.py`、不碰旧 npz、不碰 test(split==2)。
CPU-only、`--threads 1`、同一时刻只有 1 个训练进程、split 严格按数据集的 `split` 键。

**一句话结论**：FiLM（逐块 `h = h*(1+γ[style]) + β[style]`）把**整体**成簇水平推到了数据集量级
（四风格均值 p132 0.216 → 0.318，数据集 0.325），但**没有拉开风格之间的差异**：
tech/jack 的 p132 倍数从 4.29 缩到 **1.74**（数据集 8.39），排序在 jack/stamina 两支上仍然反着
（FiLM: speed 0.466 > tech 0.439 > jack 0.252 > stamina 0.115；数据集: speed 0.614 > tech 0.510 >
stamina 0.116 > jack 0.061）。**主指标未达标**；val 代价 +0.0015（未过 +0.003 线，次指标达标）。
诊断证据指向根因不是「调制方式」而是「模型几乎用不到 style」：把 val 的 style 标签换错，损失只变差
**2.02%（加性）→ 2.37%（FiLM）**。因此下一步应**按风格分模型**（§8 给了工作量估计）。

## 1. 架构改动：加性 style → FiLM

`tools/train-diffusion32-film.py` 由 `tools/train-diffusion32-burst.py` 复制（**原训练器一个字节没改**），
唯一改动是风格条件的进入方式：

```
旧（加性，baseline）               新（FiLM，本轮）
te = temb( temb_fn(t)                 te = temb( temb_fn(t)
         + c_style(style)                      + c_diff(fourier(diff)) )   # 难度仍加性进 te
         + c_diff(fourier(diff)) )    s  = style_mlp( SiLU(c_style(style)) )   # 共享风格嵌入
h  = h + temb(te)                     (γ,β) = film_head_block(s)             # 每块一个线性头
                                      h  = h * (1 + γ[style]) + β[style]     # 再进 conv2
```

```python
# Block.forward（6 个块全挂：d1/d2/d3/mid/u3/u2）
h = self.conv1(F.silu(self.norm1(x)))
h = h + self.temb(F.silu(te))[:, :, None]          # 时间步 + 难度 Fourier（与旧版一致）
if self.film is not None:
    gamma, beta = self.film(F.silu(s)).chunk(2, dim=1)
    h = h * (1.0 + gamma[:, :, None]) + beta[:, :, None]   # h = h*(1+γ)+β
h = self.conv2(F.silu(self.norm2(h)))
return h + self.skip(x)
```

几个刻意的设计选择：

| 选择 | 理由 |
|---|---|
| 风格**只**走 FiLM，不再进 `te` | 干净地检验「FiLM 本身」；`--style-cond additive` 可退回旧写法（state_dict 与旧权重 strict 兼容，实测同一份权重前向最大差 6.6e-7） |
| 6 个块全挂，每块**一个**线性头 `Linear(128 → 2*cout)` | 标准 FiLM；每块再挂 128→128 会把风格路径参数翻倍（0.255M→0.157M），而只有 4 个离散风格值要表示 |
| FiLM 头最后一层用 `std=0.05` 小随机、**不是全零** | 本仓 AUDIO-BRANCH.md 的教训：零初始化的条件支路在短训练里长不起来。实测初始化时 |γ,β|≈0.0286、四风格间 |Δγ,β|≈0.0059，第 1 步换风格就能改变输出 |
| 难度条件仍是 Fourier 加性进 `te` | 任务书要求「保留连续难度条件的 Fourier 编码与之相加」；FiLM 只接管风格 |
| 邻接加权能力全部保留 | `--adj-weight/--adj-scope/--adj-style-scale` 一字未改，本轮 `--adj-weight 0` |
| ckpt 增 `style_cond / film_blocks / style_probe`，`model_type='unet1d-film-v1'` | 采样器据此自动判别结构，旧权重仍按 `unet1d-continuous-fourier-v1` 加载 |

参数量 0.440M → **0.596M**（其中 FiLM 风格路径 0.157M）。单 epoch 时间 162–204 s（基线 195–335 s），
FiLM 的额外前向开销可忽略。

## 4. 风格分离度（本轮主指标）

**采样协议**（两档完全相同，见 `tools/film-style-separation.py`）：
每风格 5 窗、`--diff 0.5`、`--num 5`、密度对齐 `--target-occ` = 该风格数据集占位率
（tech 0.1924 / jack 0.2259 / speed 0.1939 / stamina 0.1780），
**`--sample-seed 0` 强制在去噪前重设随机数** → 四风格、跨模型的起始噪声与每步噪声**逐元素相同**，
所以「只改 style」的对照是干净的。p132 口径 = 相邻占用行间隔 == 1 的比例、跨窗口池化，
直接 import `tools/round141-burst-stats.py` 的 `pooled_stats` 计算，与 round141/143 报表可逐位相减。
FiLM 用 `diffusion32-film-last.pt`（第 9 轮既是末轮也是最优，无选择偏差）。

### 4.1 四风格 p132（对齐后）

| 风格 | 数据集 | baseline（加性） | **FiLM** | Δ(FiLM−baseline) | Δ(FiLM−数据集) |
|---|---:|---:|---:|---:|---:|
| tech | 0.5103 | 0.3962 | **0.4392** | +0.0430 | −0.0711 |
| jack | 0.0608 | 0.0923 | **0.2523** | **+0.1600** ⚠️ | **+0.1915** ⚠️ |
| speed | 0.6139 | 0.3562 | **0.4655** | +0.1093 | −0.1484 |
| stamina | 0.1160 | 0.0208 | **0.1146** | +0.0938 | **−0.0014 ✅** |

- **排序**：FiLM `speed > tech > jack > stamina`；数据集 `speed > tech > stamina > jack`
  → **不一致**。不过要说清楚哪一段是真的不一致：FiLM 的 tech 0.439 与 speed 0.466 只差 0.027，
  在 5 窗噪声底（±0.02）附近，**「speed>tech」这一段不能算验证成功**；真正稳的是**后两位反了**
  —— jack 0.252 vs stamina 0.115（差 0.14，远超噪声），而数据集是 jack 0.061 < stamina 0.116。
- **tech/jack 倍数**：baseline **4.29**（round141 公布的 4.52 是另一份噪声）→ FiLM **1.74**，
  数据集 **8.39**。差距**没有拉大，反而缩小了 2.5 倍**。
- 「成簇组均值 − 非成簇组均值」：baseline 0.320 → FiLM 0.269（数据集 0.474）→ 同样是**缩小**。
- 落在数据集 ±0.05 内的风格：**baseline 1/4（只有 jack）→ FiLM 1/4（只有 stamina）**。
  换成「命中集」看更清楚：baseline 唯一命中的是**最不该命中的 jack**（因为它本来就在数据集量级），
  FiLM 唯一命中的是 stamina；tech/speed 两个「高成簇」风格两档都没到位（FiLM 的 tech 差 −0.071、
  speed 差 −0.148）。

### 4.2 密度对齐是不是把结论带偏了？——用「原始阈值 0.5」复核

| 风格 | baseline 原始占位 / p132@0.5 | FiLM 原始占位 / p132@0.5 | 对齐后被放大的倍数（base → film） |
|---|---|---|---:|
| tech | 0.1742 / 0.3207 | 0.1617 / 0.3094 | 1.24 → 1.42 |
| jack | 0.1869 / 0.0270 | 0.1578 / 0.0527 | **3.4 → 4.8** |
| speed | 0.1822 / 0.3250 | 0.1582 / 0.3376 | 1.10 → 1.38 |
| stamina | 0.1943 / 0.0348 | 0.1617 / 0.0750 | 0.6 → 1.5 |

两点必须写清楚：

1. FiLM 的**原始**占位率整体更低（0.158–0.162 vs 基线 0.174–0.194），所以对齐时要更狠地压低阈值，
   放大倍数更大 —— jack 的对齐值 0.252 里有相当一部分是**协议对低密度风格的放大效应**（round141 也记录过
   这个效应，当时 jack 0.032→0.092 有 65% 来自对齐）。
2. 但**方向不受协议影响**：在固定阈值下 FiLM 也把 jack 0.027→0.053、stamina 0.035→0.075 抬了一倍，
   而 tech/speed 基本没动（0.321→0.309、0.325→0.338）。也就是说 **FiLM 干的事是把「不成簇」的风格
   推成「成簇」，而不是把「成簇」的风格推得更成簇** —— 这正是加性 style 时代那条
   「tech/speed 的成簇先验沿共享权重渗到 jack/stamina」的老毛病，换了调制方式后**依然存在**。

二值卷翻转率（Hamming）：

在输出空间里的影响力没有实质提升；两两 MAE 只涨了 1.4%，其中 tech–speed 反而更接近了。

## 5. 为什么 FiLM 也没拉开？（诊断，比 p132 更直接）

### 5.1 换错 style 标签的损失代价（固定 t/噪声 seed 1234，完整 val 5,025 窗）

| 模型 | 用对标签 | 用错标签（另 3 个的平均） | Δ | 相对 |
|---|---:|---:|---:|---:|
| baseline（加性） | 0.065973 | 0.067308 | +0.001335 | **+2.02%** |
| **FiLM** | 0.067445 | 0.069044 | +0.001599 | **+2.37%** |

按风格拆（Δ 为用错标签的损失增量）：baseline tech/jack/speed/stamina =
+0.00133/+0.00135/+0.00183/+0.00109，FiLM = +0.00112/+0.00202/+0.00160/+0.00167
—— FiLM 只是把「依赖 style 的量」从 tech 挪到了 jack/stamina，总量没上去。
也就是说：即使换成 FiLM，**把 style 标签完全搞错，val 只变差 2.4%**。这不是「调制方式不够强」的问题，
而是「模型主动只用了这么一点 style 信息」—— 4 个风格的 x0 分布重叠很多，MSE 目标下最优解就是
「主要学与风格无关的共同结构，style 只用来微调」。风格条件再换花样（FiLM/AdaGN/adapter）都受这条约束。

### 5.2 权重空间里 FiLM 确实学到了东西（但没有变成风格特异）

末轮 FiLM 的 γ/β（4 个风格的均值/离散度）：

| 块 | \|γ\| 均值 | 四风格间 \|Δγ\| | \|β\| 均值 | 四风格间 \|Δβ\| |
|---|---:|---:|---:|---:|
| d1 | 0.169 | 0.066 | 0.095 | 0.048 |
| d2 | 0.139 | 0.054 | 0.084 | 0.047 |
| d3 | 0.121 | 0.051 | 0.072 | 0.043 |
| mid | 0.109 | 0.050 | 0.072 | 0.041 |
| u3 | 0.127 | 0.057 | 0.074 | 0.041 |
| u2 | 0.168 | 0.050 | 0.066 | 0.032 |

γ 从初始 0.029 长到 0.11–0.17（风格嵌入两两距离 2.1–3.5），**四风格之间确实分开了 0.05 左右**。
但 FiLM 是**空间均匀**的逐通道仿射：它只能整体缩放/平移特征通道 → 落到输出上主要是
「全局密度/成簇水平的偏移」，而不是「时间结构按风格改写」。这解释了 §4.2 的现象：
所有风格的成簇水平一起被推高，风格之间的对比度反而被压平。

**结论：加性 → FiLM 不是瓶颈所在。瓶颈是「单一共享 U-Net + 弱风格信号 + 无风格区分性损失」。**

## 6. 判定

| 判定项 | 结果 |
|---|---|
| 主指标①：四风格 p132 排序与数据集一致 | ❌ `speed>tech>jack>stamina` vs `speed>tech>stamina>jack`（jack/stamina 反） |
| 主指标②：tech/speed 与 jack/stamina 差距明显拉大 | ❌ tech/jack 倍数 4.29 → **1.74**（数据集 8.39）；成簇组均值差 0.320 → 0.269（数据集 0.474） |
| 次指标：val 不显著变差（>+0.003 为代价） | ✅ **+0.00147**（0.06597 → 0.06744），代价均匀分布在四个风格上 |
| 附加：训练时长 | 9 epoch / 1714 s（基线 2413 s），FiLM 没有带来时间代价 |

**总判定：主指标未达标。** 但与「完全没变化」不同，FiLM 有一个正面的、可解释的副作用：
**四风格平均 p132 从 0.216 升到 0.318（数据集 0.325）**，其中 stamina **0.115 ≈ 数据集 0.116**（命中），
tech/speed 也各自 +0.043/+0.109。问题在于这份增量是**全局的**（jack 也被抬了 +0.160），
所以「风格可分辨度」没有改善（`style/noise` 0.412 → 0.389，两两 MAE +1.4%）。

## 7. 采样口径的一个重要注记（会影响和旧报表对数字）

本轮所有采样都用 `--sample-seed 0`（去噪前重设随机数），而 round141/143 用的是「启动时 seed + 模型构造
消耗随机数」的旧行为。**同一份 baseline 权重**、同一个 p132 口径，两套噪声给出的数不同：

| | 本轮（同噪声对照） | round141 公布 |
|---|---:|---:|
| tech | 0.3962 | 0.4148 |
| jack | 0.0923 | 0.0917 |
| speed | 0.3562 | 0.3721 |
| stamina | 0.0208 | 0.0385 |

**5 窗的抽样噪声大约 ±0.02**（stamina 甚至到 0.018）。所以：
（a）本轮 baseline 与 FiLM 的差必须用「同一份噪声」的这组数来比（已在 §4 中这样做）；
（b）小于 0.02 的差异不要当结论 —— jack 的 +0.160、speed 的 +0.109、val 的 +0.0015 都远超这个噪声底，
但「tech−speed 的 MAE 0.063→0.056」这种量级不能下结论。

## 8. 下一步：按风格分模型（fixture 建议 + 工作量估计）

证据链已足够指向这个方案：`换错 style 只差 2.4%` + `FiLM 只抬高全局成簇` + `style/noise 未提升`
= 共享权重下模型没有动力把风格用作「结构旋钮」。分模型把这个自由度直接变成「每套权重只服务一种风格」，
泄漏通路被物理切断，而且 round141 已经证明「成簇」可以靠损失权重单独调出来。

### 备注：这条方案已经在跑

写这份报告时，另一个 agent 已经建了 `tools/train-diffusion32-perstyle.py` 并在跑
`out/diffusion/round145-perstyle/`（tech，`--max-windows 4000 --time-budget 1000`）。
它的口径与本轮建议一致（split 键 + 按风格过滤 + 逐模型自己的 `--adj-weight`），
只是每轮窗口数取 4000（≈本轮一半，单模型 ~12 min）；本节的估计可与那组实验互相校验。

### 方案（推荐顺序）

1. **训练器加 `--only-style S`（或 `--n-style 1`）**：在现有 split 逻辑之后再加一层
   `style == S` 过滤（train 仍只用 split==0，val 仍只用 split==1）。`n_style=1` 时风格条件退化成常量，
   可整条去掉（保留难度 Fourier 条件）。
2. **每个风格一套 ckpt**：`--adj-weight` 用 round141 外推的 `a_s = [0.85, 0, 1.45, 0.75]`（tech/jack/speed/stamina）
   作为第一档，每个模型只用自己那一个 a，不再需要 `--adj-style-scale`。
3. **采样器**：`sample-diffusion32film.py --ckpt <该风格的 ckpt>`，`--style` 传对应下标即可
   （`n_style=1` 时传 0）；`--target-occ` 继续用该风格的占位率。
4. **验收**：`tools/film-style-separation.py` 支持「每个 style 一个 ckpt」，四风格分开跑 5 窗，
   p132 与两两差异照旧（此时两两差异来自不同模型，不再有「同一份噪声」的逐窗对齐优势，
   MAE 只能作量级参考，p132 与数据集比仍是主指标）。

### 工作量估计

| 项 | 估计 | 依据 |
|---|---|---|
| 代码改动（训练器 `--only-style`/`--n-style`、采样器小改、验收脚本支持多 ckpt） | **1–2 h** | 都在现有文件上加减几十行，无新依赖 |
| 训练 | **4 × 9 epoch ≈ 4 × 1500 s ≈ 100 min**（单进程串行） | 本轮 9 epoch = 1714 s（含 val/A-B）；每风格每 epoch 仍抽 8000 窗（speed 只有 11,141 窗、33 组，group-cap 后够用） |
| 采样验收 | **≈ 5 min**（4 模型 × 5 窗，每窗 ~5 s） | 本轮 8 次采样共 ~5 min |
| 数据量是否够 | 够：tech 14,818 窗/478 谱/26 组、jack 29,115/927/51、speed 11,141/385/33、stamina 31,935/509/43（均 split==0） | 分模型后每模型的数据量与「共享模型的 1/4」不是一回事，风格本来就是数据分割标签，没有信息损失 |
| 风险① val 噪声 | 每风格 val 只有 25–51 谱 / 867–2,068 窗 | 单模型 val 的绝对值波动更大，比较只在同模型同轮次内做 |
| 风险② 超参不复用 | round141 的 `a_s` 是在「有泄漏」的条件下外推的，分模型后 jack 不再被泄漏抬高 → 它自己的 a=0 就该贴近数据集 0.061；tech/speed 需要的 a 可能比 0.85/1.45 更小 | 第一档先跑 `a_s=[0.85,0,1.45,0.75]`，若 tech/speed 过冲再各降一档（每档 +9 epoch ≈ 25 min） |
| 风险③ 工程 | 4 份权重 → 采样/推理要按风格选模型；谱包生成链路要传入「风格 → 模型路径」的映射 | 属于接口改动，不影响本轮统计结论 |

**总投入**：首轮 4 个分模型（含验收）约 **2 h 工程 + 100 min 算力**，比继续在共享模型上调 FiLM/损失更划算
（round141 的损失调参与本轮 FiLM 都撞在同一堵墙上）。
