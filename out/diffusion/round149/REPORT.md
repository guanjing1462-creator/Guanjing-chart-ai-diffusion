# 第 149 轮：采音数据的病因查明并修好（一格相位差）

## 一、真正的病因：**不是秒级错位，是一格（≈40ms）相位差**
上一轮我报告「28/48 包位移 >200ms，最大 −2400ms」。**这轮被证伪了**：
250ms 分箱口径**没有判别力**——随机位移的相关基线就有 **+0.383**，峰 Δr 只有 0.06 量级，
所以「最佳位移」取到哪算哪，我看到的 −2400ms 是假峰。

**真正的问题是**：旧数据集的音频条件 C 比音符 X **系统性地晚约一格（1/32 格 ≈40ms）**。
- δ=0 时逐谱 X–C 相关中位 **−0.062**（仅 16% 达 0.25）
- δ=+50ms 时 **+0.498**

**一格错位就让条件几乎完全失效** —— 这是采音训练失败的直接原因。

## 二、重建结果（`out/diff-data-audio-fixed/dataset.npz`）
对每张 4K mania 谱**独立**搜索最佳位移（50ms 步长，±2500ms），
用「X–C 的 1/32 格相关」做门禁（`r* ≥ 0.25 且 |shift*| ≤ 300ms`）：

| 项 | 值 |
|---|---|
| 4K mania 谱总数 | 226 |
| **保留** | **114 张 / 2887 窗 / 25 首歌** |
| 拒绝 | large_shift 68 / variable_bpm 24 / low_r 18 / no_window 2 |
| 校正位移 | 中位 **+50ms**，104/114 落在 +50（δ*=0 的只有 11/114） |

### 自证（与门禁同口径，直接在产出 npz 上重算）
| 指标 | **新数据集** | 旧数据集 |
|---|---|---|
| **r 中位** | **+0.498** | −0.062 |
| r 最小 | **+0.269** | −0.429 |
| r ≥ 0.25 占比 | **100%** | 16% |
| r ≥ 0.40 占比 | 77% | 6% |
| 随机平移 C 对照 | −0.007 | −0.009 |

### 关键独立证据：相位敏感（证明不是「自证自己」）
把 C 平移后重算相关：
| 平移 | r 中位 |
|---|---|
| **0 格** | **+0.498** |
| 1 格（≈40ms） | **−0.154** |
| 2 格 | +0.084 |
| 4 格 | +0.364 |
| 8 格 | +0.420 |
| 随机循环平移 | −0.007 |

**峰值只在 lag=0、平移一格就塌** → 相关来自「音符落在哪个 1/32 格」的相位对齐，
不是慢变的响度包络。

## 六、方法学教训（值得记住）
**指标分辨率必须匹配信号尺度。** 我用 250ms 分箱去找位移，而真正的对齐尺度是 40ms（1/32 格），
导致整轮结论错误；而 1/32 格口径一用，病因立刻显现。
**以后任何「对齐/相位」类指标，分箱必须 ≤ 目标精度的 1/2。**
