# 第 140 轮：按风格标定密度（占位率精确匹配）

## 一、做了什么
上一轮定位到「密度维度被压平」：数据集里 jack 0.226 > speed 0.194 ≈ tech 0.192 > stamina 0.178，
但生成时四个风格都挤在 0.215 附近。

新增 `tools/sample-diffusion32occ.py` 的 `--target-occ`：
给定目标占位率，**按概率图的分位数反解解码阈值**（`thr = quantile(P, 1−occ)`），
使解码后的占位率精确等于目标——这是标准的按密度标定，不是后处理造假。

## 二、四风格实测（diff 条件固定 0.5，各 5 窗口）

| 风格 | 目标占位率 | **实测占位率** | 反解阈值 |
|---|---|---|---|
| tech | 0.1924 | **0.1924** ✅ | 0.3741 |
| jack | 0.2259 | **0.2260** ✅ | 0.1585 |
| speed | 0.1939 | **0.1939** ✅ | 0.4212 |
| stamina | 0.1780 | **0.1781** ✅ | 0.7486 |

**占位率现在可以精确控制到小数点后 4 位**，风格间的密度差（0.178–0.226）被完整复现。

## 三、但 p132 在「密度对齐」后暴露了真实差距
| 风格 | 数据集(占位/p132) | 生成(占位/p132) | p132 差 |
|---|---|---|---|
| tech | 0.1924 / 0.510 | 0.1924 / 0.415 | **−0.095** |
| jack | 0.2259 / 0.061 | 0.2260 / 0.092 | +0.031 |
| **speed** | 0.1939 / **0.614** | 0.1939 / **0.372** | **−0.242** ⚠️ |
| stamina | 0.1780 / 0.116 | 0.1781 / 0.038 | −0.078 |

**注意：这修正了上一轮的说法。** 上一轮在「生成密度偏高（0.215 vs 0.194）」时测出 p132 接近数据集，
那是密度偏高带来的副作用；**密度对齐后，模型其实比数据「更均匀、更少爆发」**，
speed 档差距最大（0.372 vs 0.614）。

含义：数据里的 1/32 是**成簇出现**的（burst），模型学到的是**均匀撒点**。
这正是「节奏结构」层面还没学到位的地方。

|---|---|---|

## 五、结论与下一步
| 项 | 状态 |
|---|---|
| 密度按风格精确控制 | ✅ **已实现**（`--target-occ`，误差 <0.0001） |
| 风格间密度差复现 | ✅ 0.178–0.226 |
| 1/32 的成簇结构（p132） | ⚠️ 偏均匀，speed 差 −0.242 |
| 难度可控 | ✅（速度档 12.67，条件可调） |
| 键型标签 | ⚠️ Koishi 标签噪声大（人类自身一致性仅 42–45%） |

**下一轮**：针对「成簇」做训练侧改动（而不是采样侧）——
把损失的权重按邻接（是否与相邻格成对）加权，或按「连续 1/32 链」分段加权，
让模型学会在中段爆发、而不是全程均匀。
