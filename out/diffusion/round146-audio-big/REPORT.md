# Round 146 · 大规模音频条件（踩音）训练集

目标：给 GJ 扩散模型造「人类谱面 + 音频」对齐的音频条件训练集，解决扩散模型完全没采音（密度-强度相关 +0.14 ≈ 随机）的短板。

> 全部数据来自 osu.direct 镜像（搜索 API + `/api/d/<SetID>` 下载 .osz，每个 beatmapset 自带音频），CPU-only，不训练模型。

## 2. 数据集

- 路径：`out/diff-data-audio-big/dataset.npz`（5.1 MB）
- 接受谱面（4K mania 且红线 ≤3）：**200 张**，来自 40 个谱面包 / 40 首歌（下载的 48 个 set 里有 8 个最终没有可用 4K 谱面：全是非 4K 转换谱或超过 3 条红线）
- 窗口数：**5279**，`X` (5279, 4, 256) uint8，`C` (5279, 256, 4) float16

| 键 | dtype | 含义 |
| --- | --- | --- |
| `X` | uint8 [5279, 4, 256] | 每键每 1/32 格是否有音符（LN 持续段计入）|
| `C` | float16 [5279, 256, 4] | 四带 onset 强度（low 0-200 / mid 200-2k / high 2k-8k / total）|
| `song` | int16 | 歌索引（→ `songs`）|
| `chart_id` | <U32 | 谱面 id，形如 `SetID-难度名` |
| `split` | int8 | 0/1/2 = train/val/test，**按 set 分组，同 set 不跨集** |
| `start_cell` | int32 | 窗口在谱面 1/32 网格上的起始格号 |
| `bpm` | float32 | 该谱首红线的 BPM（60000/beatLength）|

split 分布：train 4222 (80.0%) / val 532 (10.1%) / test 525 (9.9%)，按谱面包（set）整体划分。

构造口径：

- **网格**：读 `[TimingPoints]` 中第一条 `uninherited=1` 的 `beatLength`，`step = beatLength/8` 毫秒（1/32 拍），起点 = 该红线 `offset`；红线数 >3 的变速谱跳过（24 张）。
- **特征**：22.05kHz 单声道 → STFT n_fft=512/hop=128 → 128 带 mel(0-8k) → log1p → 沿时间正差分取正 → 四带求和 → 每格取格内 max → 每首每通道 P99 归一（与 `tools/audio-cond-data.py` 同一实现，直接 import 复用）。
- **窗口**：`[4,256]`，stride 128 格（≈128×step ms），保留 音符数 ≥16 且 条件覆盖率 ≥90% 的窗口。

构建阶段跳过：多红线 24，无红线 0，无音频 0，读谱失败 0，非4K 17，时长不足 0。

### 3.1 对齐诊断（为什么 250ms 口径的 r 偏低）

第一版构建有一处真实错误：**多曲 pack 的 set 里每张谱对应不同音频**，最初按 set 只取了一首音频做特征，导致这些谱的条件与音符错位（48 个 set 里有 24 个是多音频 pack）。改为「每张谱取自己的 `AudioFilename`」后重建，上表数字即修正后的结果。

| 指标 | osu.direct 新数据 | 本地 6 首人工谱（同口径标定）|
| --- | --- | --- |
| 250ms 分箱 r 中位 | 0.225 | 0.277 |
| 500ms 分箱 r 中位 | 0.283 | 0.353 |
| 1000ms 分箱 r 中位 | 0.353 | 0.428 |
| ±3s 平移扫描的最佳 r 中位 | 0.3 | 0.313 |
| 最佳 r 处的平移量中位 | -650 | -750 |

本地 6 首人工谱（已知正确对齐）在**同一 250ms 口径**下 r 中位只有 0.277，说明这个指标本身对高密度 4K 谱面不敏感：

- 4K 谱在 stream/jumpstream 段落里音符间隔只有 60-120ms，250ms 桶里的「音符数」几乎是常数，方差被压平，r 自然被衰减；
- 把分箱放宽到 500ms / 1000ms，同一批数据 r 中位升到 0.283 / 0.353，说明对齐关系真实存在、只是被细粒度分箱吃掉了；
- **最关键的一条**：直接用数据集里真正训练的 `C` 特征（1/32 格四带）重建到 250ms 再与音符密度相关，上表 `r(C 1/32 口径)` 一列普遍在 0.5-0.67，远高于原始 onset 包络口径 —— 说明「1/32 网格 + 首红线 offset + 四带特征」这套管线本身是对的，训练用的条件确实踩在音符上。

三项被指定的排查项结论：

（诊断里还算过一个「音频 onset 落在音符 ±50ms 内」的命中率，但 4K 谱面音符已密到每 60-120ms 一个，随机对照也有 0.72-0.94，该指标对高密度谱没有区分力，故不作为结论依据。）

1. **网格起点**：用首条 `uninherited=1` 红线的 offset 作第 0 格，音符头落格率中位 0.99（最小 0.02）—— 除极少数含未吸附音符的谱外，落格率≈1 说明起点与 step 都取对了。
2. **1/16 vs 1/32 换算**：`step = beatLength/8`。若误用 1/16 会得到 2 倍 step，落格率会掉到 0.5 附近；实测中位 0.99，不存在半格/双格错位。上表里落格率 0.02 / 0.18 的两张是含大量未吸附音符的 rate/LN pack（其 `C` 口径仍有 0.61 / 0.68），属谱面本身不吸附，非换算错误。
3. **音频起点 offset**：.osz 内音频从 0 开始，网格直接用红线的绝对毫秒当音频时间轴（未叠加 `AudioLeadIn`）。±3s/100ms 步长的粗扫描峰值出现在 -650ms，但**本地已知正确的 6 首人工谱同样是 -750ms**、提升幅度也相近 —— 这是 250ms 分箱口径 + 音频编码延迟带来的指标级系统性偏移，而非本数据集特有的错位；若真有整体 lead-in 错位，只会体现在新数据上。

## 4. 剩余限制

1. **规模**：48 个 set / 上述窗口数，相对「大规模」仍偏小；镜像 503 比例不低，扩量需要更长的抓取窗口与重试。
2. **谱面多样性**：搜索关键词集中在 jumpstream / tech / jack / stamina / LN 等竞技向 pack，低难度与 ez/新手向谱面偏少，训练出的条件分支可能对低密度区间覆盖不足。
3. **变速谱**被策略性排除（>3 条红线），这类曲子（占真人谱相当比例）目前进不了训练集。
4. **条件特征仍是 4 带包络**，不是完整 mel 张量；接口与 Mug 的 mel 同参数，但要换成 128 带 mel 需要重跑特征（这一步纯 CPU，成本不高）。
5. **P99 归一化是按单首归一**，跨曲的绝对强度不可比；若模型需要全局一致的响度语义，要改成全局分位数。
6. 250ms 口径的 r 中位刚过 0.20 门槛（见上表），同一批数据在 500ms/1000ms 口径与 `C` 口径下显著更高；做训练数据质量门禁时建议用 `C` 口径（0.5+）而不是 250ms 密度口径。
7. 相关性中位 ≈ 0.3-0.4 属于「节奏对齐确实存在但并非一一对应」的水平：谱面密度还受作者风格、难度目标影响，音频强度不是唯一解释变量。这个水平足以让扩散模型学到「踩音」，但不能指望它单独决定密度。
