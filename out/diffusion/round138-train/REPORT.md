# Round138 · GJ 无泄漏（分组 split）训练 · 泄漏量化 · 采样验收

**范围**：只训练 + 验证 + 采样统计。不生成谱包、不产出 `.osz`、不碰 test 做任何调参。
**一句话结论**：按 `split` 训练 9 轮（40 分钟，CPU 单线程），val 0.0813 → **0.0660**；
用同一份权重做 A/B，泄漏式验证集只比无泄漏 val **低 0.0010（+1.5%）**，且被训练见过的窗口
反而略差 —— **在这个模型规模/训练预算下，窗口级泄漏没有造成可测的记忆红利**；
test 只跑一次为 0.0640，不比 val 更差；采样侧难度条件单调（4/4 style），
但 p132（1/32 连打占比）0.11–0.79 明显偏离数据集 0.2637。

口径要点（避免误读）：

- **p132 格口径 vs 毫秒口径必须分开报**：数据集里 14.61% 的音符是 1/48 三连音等非 1/32 内容，
  被量化吸到格点上，所以 0.2637（格）≠ 0.2545（毫秒），都不能直接当「人类真值」。
- **生成卷的两个口径恒等**：生成侧严格等格长、无 timing 抖动，1 格间隔恒等于 0.5 个 step16，
  恒落在 `[0.35,0.75)` 区间 → 采样统计只报格口径，毫秒口径不提供新信息（本报告不拿它冒充差异）。
- 占位率/p132 一律 **池化**（跨窗口累加后相除），与数据集报告同算法。
- 连续难度条件的 5%/95% 归一化 **只在 train 上拟合**（lo=0.0625, hi=0.3633），
  val/test 只做变换，不参与拟合（旧的随机切分版是全量拟合，属轻度泄漏）。

## 2. 训练器改动：`tools/train-diffusion32-grouped.py`

由 `tools/train-diffusion32c.py` 复制后只改划分/抽样/记录，模型与损失逐字节不变：

1. **删掉随机窗口切分**：读 `split` 键，train 只取 `split==0`、val 只取 `split==1`。
   没有 `split` 键直接报错退出；传 `--val-frac>0` 直接报错 —— 不允许回退到 `torch.randperm` 切分。
2. **每 epoch 从 train 无放回抽 8000 窗**（`--max-windows`），val 用**完整 5,025 窗**。
3. **组上限抽样 `--group-cap 300`**（父代理要求，见下）：先每组最多取 300 窗，合并成
   27,110 窗的池子，再均匀抽 8,000。train 与 B 集（泄漏式验证）走**同一条 `draw_pool`**。
   原因：train 141 组里最大一组 32,513 窗（占 37%），前 3 组占 47%，纯按窗口均匀抽会被
   少数大组主导 —— val 数字好看但泛化差。实测每 epoch 覆盖 **140 组**，单组最多 **108 窗**。
4. 连续难度条件 = 占位率按 train 5/95 分位归一化（`lo/hi` 存进 ckpt，采样器 `--diff` 直接吃
   这个值，**采样器接口未改**）。
5. ckpt 记录 `split_policy / train_groups / val_groups / val_n_groups / train_windows_seen /
   val_window_source / train_window_source / leak_ab`。
6. 验证同时报 **池化**与**组均**（先算 17 个 val 组的组内均值、再对组取平均），
   组均不会被多窗大组拉偏，更能反映跨组泛化。

## 3. 配置与耗时

```
--pred x0 --base 48 --batch 32 --threads 1
--max-windows 8000 --epochs 12 --group-cap 300 --ab-n 5025
--time-budget 2340 --min-epochs 9
数据 out/diff-data-grouped/dataset.npz
```

| 项 | 值 |
|---|---|
| 参数量 | 0.440M（cond_dim=0，无条件音频分支） |
| 线程 | torch 1（internop 1），**同时只有 1 个训练进程** |
| 每 epoch | 250 batch；干净时 195s，宿主机被争用时 248–336s |
| 轮数 | **9**（第 10 轮触发 2340s 时间预算，按纪律停） |
| 总训练时长 | **2,413s ≈ 40.2 分钟**（含每轮 val + 收尾 A/B） |
| 内存 | 常驻 RSS ≈ 590MB（X 只在抽到的那批转 float32，全量 train 不展开） |

先测单 epoch：195s（8000 窗 + 5,025 窗 val）→ 按 45 分钟预算定为 9–12 轮，
实际因机器被别的进程抢占（单 batch 673→1420ms）在 9 轮收手，仍在预算内。

## 5. A/B 泄漏量化（核心证据）

**协议**：同一份权重（末轮 `…-last.pt`，**没有经过 val 挑选，无选择偏差**）；
两侧都是 5,025 窗；固定 t 与噪声（generator seed 1234，按长度生成，两侧逐元素相同）；
未加权 MSE，x0 目标。只有窗口来源不同：

- **A** = `split==1` 的全部 5,025 窗 / 17 组 / 148 谱 —— 无泄漏。
- **B** = 从 `split==0` 用**与训练相同的 `draw_pool`（组上限 300）**抽 5,025 窗 / 139 组。
- **B_uniform** = 从 `split==0` **纯均匀**随机抽 5,025 窗 / 134 组（旧做法的字面复刻，做敏感性检查）。

| 集合 | 窗数 | 组数 | 池化损失 | 组均 |
|---|---:|---:|---:|---:|
| **A** `split==1`（无泄漏） | 5,025 | 17 | **0.0660** | 0.0669 |
| **B** `split==0` 按组上限抽 | 5,025 | 139 | 0.0670 | 0.0663 |
| **B_uniform** `split==0` 纯均匀 | 5,025 | 134 | 0.0674 | 0.0670 |
| 末轮训练池（8000 窗） | 8,000 | 141 | 0.0660 | — |

**差值（B − A）= +0.0010（相对 A +1.5%）**；纯均匀版 **+0.0014（+2.1%）**。
方向是 B **更差**，也就是说「从训练池里抽验证集」在这份权重上**没有变漂亮**。

### 5.1 为什么没变漂亮：记忆分解（`leak-decomp.json`）

按训练器同样的 `draw_pool` 与种子重建每轮抽到的行号：9 轮 × 8000 抽，去重后
**35,599 窗 = train 的 40.9%** 被真正训练过。B 集里 **4,070 窗（81.0%）见过**、955 窗（19.0%）没见过。

| 子集 | 窗数 | 池化损失 |
|---|---:|---:|
| B_seen（训练见过） | 4,070 | 0.0681 |
| B_unseen（训练没见过） | 955 | 0.0669 |

`B_seen − B_unseen = +0.0012` —— 见过的窗口**并不更准**（差在噪声量级内，方向还是反的）。

解释（可检验）：模型只有 0.44M 参数、只训练了约 0.83 个 train 采样量（9×8000/87009），
容量与时间都不足以记住 95,574×1024 个格子的具体内容；再加上组上限把每个大组的贡献压到
≤108 窗/轮，同曲窗口在训练里出现得很稀疏。**在这个训练预算下，泄漏给不了记忆红利。**

### 5.2 那「旧 val 0.0811」到底虚在哪

- **直接量化**：如果按旧做法（窗口随机切、val 从训练池里抽）来报，本配置会得到
  0.0674 而不是 0.0660 —— 虚高幅度约 **2%**，不是数量级。
- 但旧口径有两个**不是「虚高%」能描述**的问题：
  1. 它测的是「同曲/同组窗口」，跨谱泛化完全没有被检验（本报告 A 才是）；本轮的
     test 组均 0.0621 与 val 组均 0.0669 差 0.005，比 A/B 的 0.001 大一个量级 ——
     真正有信息量的是**跨谱差异**，泄漏那点差值在这个尺度上被淹没。
  2. 旧的 0.0811 与本轮的 0.0660/0.0670 **不可比**：数据集换了（旧的 `out/diff-data32`
     没有 split/group，没法证明无泄漏）、难度条件归一化的拟合集不同、训练轮数不同。
     所以正确的说法不是「旧数虚了 X 倍」，而是「旧数不可用于跨 run 比较」。
- 结论：**这次的 val 数字可信**（有跨组泛化证据、test 独立复核），旧 val 的毛病主要是
  「测错对象 + 不可比」，而不是被窗口级记忆撑爆。

**难度条件单调性：4/4 个 style 严格单调**（diff 0.1 → 0.5 → 0.7，占位率与每窗音符数都递增）：

- style0 0.0771 → 0.2148 → 0.2905（音符 79 → 220 → 298）
- style1 0.0884 → 0.2148 → 0.2773（91 → 220 → 284）
- style2 0.0859 → 0.2202 → 0.2876（88 → 226 → 295）
- style3 0.0801 → 0.2144 → 0.2764（82 → 220 → 283）

**与数据集对比**：

| 指标 | 采样 | 数据集 | 差 |
|---|---:|---:|---:|
| 占位率 @ diff 0.5 | 0.2148（style0）；四风格 0.2144–0.2202 | 0.1986 全量 / 0.1845 val | +0.016～+0.036 |
| 占位率 全 12 条件池化 | 0.1940 | 0.1986 | −0.0046 |
| **p132 @ diff 0.5** | **0.1152–0.5930** | **0.2637** | 风格间差 5 倍 |
| p132 全 12 条件池化 | 0.4684 | 0.2637 | +0.2047 |

解读：

- **占位率基本对得上**：diff≈0.45 恰好等价于数据集均值 0.1986（(0.1986−0.0625)/0.3008=0.4525），
  模型在 diff 0.5 给出 0.2148，条件几乎是校准的（略偏高 8%）。12 条件池化的 0.1940
  之所以贴近 0.1986 只是采样网格的巧合，不要当精度证据。
- **p132 明显不对**：diff≥0.5 时 style0/2 给到 0.57–0.79，是数据集的 2–3 倍，
  说明模型倾向于「每格都填」的等距连打（mode collapse 到规整 stream）；style1（jack）反而
  只有 0.115–0.140（比数据集低一半），style3 居中（0.29–0.58）。
  即：**密度维度学到了，节奏/型态维度只学到了「按风格分化的两种极端」**。
  这与「0.44M 参数 + 9 轮 x0 MSE」的容量相符，也比旧的随机切分版更容易暴露（因为现在知道
  每个 style 该有多规整）。
- 采样每条件仅 2 窗，p132/占位率的点估计标准误不小；但 style 间 0.11 vs 0.79 的差距
  远大于噪音，方向性结论可信。

**转换抽检**（只落到 `/tmp`，不出包）：`roll-s0d0.7-seed0-00`（293 HitObjects）与
`roll-s1d0.5-seed0-01`（222）转成 `.osu` 成功，与卷统计的音符数一致（297.5/220），
说明二值卷到谱面的往返没问题。

## 8. 结论

1. **划分纪律已落实**：训练/验证严格按 `split` 键，随机窗口切分被代码层面禁掉
   （无 `split` 或传 `--val-frac` 都直接报错）；test 只在最后跑了一次。
2. **本轮 val 可信**：val 0.06597（组均 0.06691），未在 val 上选型；test 一次为
   0.0640/0.0621，不劣于 val；A/B 差值 +1.5% 说明泄漏在这份训练预算下带不来便宜。
3. **旧 val 0.0811 的问题是「不可比 + 测错对象」**，实测虚高约 2%（本配置等价口径 0.0674 vs
   0.0660），不是数量级虚高 —— 但它确实完全没有检验跨谱泛化，这一点是致命的。
4. **生成侧**：难度条件单调（4/4），占位率与数据集吻合，**p132 显著偏高/过规整**，
   且风格分化过头（tech/speed 满格连打、jack 过于稀疏）。下一轮要修的是节奏规整度
   （例如给 x0 目标的稀疏度校准、或按 style 的 p132 做采样端温度/阈值调整），而不是再加大训练。

### 限制（别把这些当已验证）

- 9 轮、约 0.83 个 train 采样量，**未收敛**；不能把「A/B 差值小」外推到长训练 ——
  记忆红利需要容量与时间，更长的训练很可能把 A/B 差值拉大。要复现这个结论请沿用同一预算。
- 泄漏量化的 B 有两个版本（组上限 + 纯均匀），两者差 0.0004，一致指向「B 不比 A 好」。
- 采样统计只覆盖 diff ∈ {0.1,0.5,0.7} × 4 style × 2 窗 × 1 seed，不含极端 diff 与多 seed 方差。
- 难度条件仍是「占位率归一化」，**不是**已标定的 Koishi 定数；采样器 `--diff` 与它同尺度。
- p132 的毫秒口径对生成卷退化为同一数，数据集侧 0.2545 与格口径 0.2637 的差异
  （量化效应）本报告没有在生成侧复现，因为生成侧没有真实 timing。
