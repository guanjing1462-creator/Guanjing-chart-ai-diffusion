### 1.2 为什么不能用旧集

## 3. 验收方法（核心：配对 vs 错配，而不是 val 损失）

`tools/eval-audio-follow.py`。采样沿用 `tools/sample-diffusion32c.py` 的 DDPM 公式
（`prediction_to_x0` + 后验均值，200 步，阈值 0.5），只把 `--diff` 与 `--cond` 从标量扩成逐窗口。

- **窗口**：val 抽 **24** 窗（6 首歌 × 4，按占位率分层，占位率 0.016–0.781）；
  test 抽 **20** 窗（5 首歌 × 4，0.016–0.491）。
- **配对设计**：所有对照组用**同一初始噪声**（seed 20251），只改条件 —— 差异只能来自条件。
- **条件**：`C[idx]`（该窗真实音频特征），难度条件 = 该窗人类占位率归一化。
- **对照组**（这是本轮的关键设计）：
  1. `A-无条件`：模型 A，没有音频分支；
  2. `B-零条件`：**同一份 B 权重**，条件置零；
  3. `B-错配`：B 的条件换成**另一窗（打乱 song/start_cell）的 C 与难度**，
     指标既对「它拿到的那个 C」算，也**对该窗真 C** 算（后者才是最干净的无采音基线）；
  4. `B-配对·事后错配C`：不重采样，只把 B-配对的样本与错配 C 算相关；
  5. `B-条件±1格 / ±4格`：条件整体平移 1 格（≈40ms）或 4 格（≈160ms = 分支一个 stride 单位）。
- **指标①**：分箱后音符密度 vs `C` 总带强度的 Pearson r（**250ms** 与 **1000ms** 两种分箱；
  四带都算，正文用「总」）。人类同批谱面同口径作参照。
- **指标②**：音符落在 1/32 细分格（`(start_cell+k)` 为奇数）且该格 `C总` 高于窗内中位的比例
  `p_odd_hi`。**注意它的结构基线不是 0.5**：本数据集里高 C 格偏向奇数格，
  均匀摆放的音符会得到 **0.639（val）/ 0.604（test）**（脚本里现算），人类 0.813 / 0.785。
- 统计：逐窗口配对差 + Wilcoxon 符号秩检验（n=24 / 20）。

### 4.2 配对 vs 错配（**核心判据**）

| 对比 | r250 差值 | r1000 差值 | 胜负 | Wilcoxon p |
| --- | --- | --- | --- | --- |
| **B-配对 − B-错配（对真 C）** | **+0.223** | **+0.265** | **24胜0负 / 20胜4负** | **1.2e-7 / 3.7e-5** |
| B-配对 − B-零条件 | +0.192 | +0.175 | 23胜1负 | 2.4e-7 |
| B-配对 − A-无条件 | +0.142 | +0.141 | 22胜2负 | 3.0e-5 |
| B-配对 − B-配对·事后错配C | +0.170 | +0.124 | 19胜5负 | 1.2e-3 |
| B-配对·占用校准 − A·占用校准 | +0.191 | +0.274 | 20胜4负 | 3.0e-5 |
| B-配对 − 人类（同批真谱） | −0.130 | −0.209 | 8胜16负 | 0.095 / 0.039 |

**怎么读这张表**：

1. **B 确实跟着条件走**：把条件换成别的窗的 C 后，B 的输出与**真 C** 的相关掉到 −0.058，
   而给真 C 时是 0.207（**24 个窗口全胜**，p=1.2e-7）。这是「采音」最直接的证据。
2. **B 服从的是「给它的那个 C」**：错配采样后，它的输出与**给它的外来 C** 的相关仍有 0.171 ——
   与配对时的 0.207 无显著差（+0.035，p=0.36）。这不是「没采音」，而是**条件保真**：
   模型学会了「按输入的条件生成」，本来就无法知道哪段音频「属于」这个窗口。
   → 因此**「错配采样」不能当作无采音基线**，真正的无采音基线是 A / 零条件 / 对真 C 的错配（都 ≈0）。
3. **A 的 0.080 是「密度先验」地板**：A 完全看不到音频，却仍有 0.080 —— 人类谱面在窗内的
   位置/密度先验与 C 的慢变成分偶然一致（其 ±1 格扫描为 0.052 / −0.010、±4 格 0.058 / 0.050，
   属于宽带的弱相关，不是尖峰；B 同一位置是 0.139 / 0.098 与 0.054 / 0.088）。
   所以 B 的 0.207 里，**音频专属部分约 0.13**（0.207 − 0.080）。
4. **离人类还有距离**：0.207 / 0.351 = **59%**（250ms），0.144 / 0.476 = **30%**（1000ms）。

### 4.4 相位敏感性：条件平移 1 格 vs 4 格

| 组（val / test） | r250 | r1000 | 说明 |
| --- | --- | --- | --- |
| B-配对（给真 C） | 0.207 / 0.165 | 0.144 / 0.066 | 基准 |
| B-条件 **+1 格**（≈40ms），对**给定** C | **0.002 / −0.042** | 0.071 / 0.043 | 塌掉（−0.173，p=3.9e-6） |
| B-条件 **−1 格**，对给定 C | 0.116 / −0.014 | 0.245 / 0.037 | 塌掉（−0.09） |
| B-条件 **+4 格**（≈160ms），对给定 C | 0.157 / 0.193 | 0.130 / 0.092 | **不塌**（−0.026，p=0.64） |
| B-条件 **−4 格**，对给定 C | 0.156 / 0.168 | 0.104 / 0.125 | 不塌 |

解释（这一点必须说清）：**1 格平移塌掉不代表学到了 40ms 级相位**。条件分支是
`Conv1d(k=3) → Conv1d(k=3) → Conv1d(k=4, s=4)`，每 4 格只取 1 个位置：平移 1 格会把
下采样后的条件序列整体**换成另一组采样点（混叠）**，等于给了一个「不是平移、而是变了样」的条件；
而平移 **4 格**正好是一个 stride 单位，是可以被分支表示的平移 —— 此时输出**跟着平移**
（对给定 C 仍有 0.157 / 0.193）。所以正确的结论是：

> **模型学到的相位精度 ≈ 160ms（4 格，受分支 stride 限制），不是 40ms（1 格）。**

`r250` 的格移位扫描（val 中位）也支持这一点：

| 组 | −8格 | −4格 | −2格 | −1格 | **0** | +1格 | +2格 | +4格 | +8格 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 人类 | 0.201 | 0.228 | 0.223 | 0.334 | **0.351** | 0.156 | 0.055 | 0.143 | 0.227 |
| B-配对 | 0.103 | 0.054 | 0.134 | 0.139 | **0.207** | 0.098 | 0.101 | 0.088 | 0.096 |
| A-无条件 | 0.014 | 0.058 | 0.027 | 0.052 | **0.080** | −0.010 | 0.002 | 0.050 | 0.010 |
| B-零条件 | 0.019 | 0.004 | −0.024 | 0.003 | **0.009** | −0.089 | −0.024 | 0.008 | 0.010 |

B 的峰-背景差（0 处 − ±8 格均值，val）= 0.207 − 0.100 = **0.108**；人类 = 0.351 − 0.214 = 0.137，
即「相位锁定成分」约为人类的 79%。**但这一条在 test 上不稳**：B 为 0.165 − 0.110 = 0.054，
人类为 0.394 − 0.129 = 0.265。所以「峰-背景差接近人类」只在 val 成立，
**不能当作稳健结论**；稳健的是 4.2 的配对 vs 错配对比（两个 split 都复现）。

### 4.5 踩格指标 `p_odd_hi`：**没学到** 1/32 格级相位

| 组（val / test） | p_odd_hi | 相对结构基线 |
| --- | --- | --- |
| 结构零假设（均匀音符） | 0.639 / 0.604 | 0 |
| 人类 | 0.813 / 0.785 | **+0.174 / +0.181** |
| A-无条件 | 0.703 / 0.666 | +0.064 / +0.062 |
| B-配对 | 0.727 / 0.699 | +0.087 / +0.095 |
| B-错配（对其给定的 C） | 0.727 / 0.699 | +0.087 / +0.095 |
| B-零条件 | 0.687 / 0.655 | +0.048 / +0.051 |

**配对与错配的 p_odd_hi 完全一样（0.727 vs 0.727）**，说明模型没有把音符放到「条件说该响的
那一个 1/32 格」上；它只是比 A 稍微更懂「哪里密」（和 4.1 的密度结论一致）。
`B-条件±1格` 行的 p_odd_hi 掉到 0.35–0.42（val +1格 0.35 / test −1格 0.42），同样因为条件被混叠破坏（4.4）。

**但必须说明这个指标的结构性弱点**：本数据集 1/32 格上 C 强度本身就有强烈的奇偶结构
（均匀音符基线 0.639/0.604），配对/错配的对比才是有效信息；单看绝对值会高估模型的踩格能力。

| --- | --- | --- | --- |
| B-配对 vs B-零条件 | 0.0897 | 5.95% | −0.002 |
| B-配对 vs B-错配（换内容） | **0.1993** | **14.9%** | +0.001 |

### 4.7 样本本身的质量

模型在阈值 0.5 下平均占用 0.167–0.176（人类 0.230），偏稀 25%；用占用校准阈值后达到 0.230，
r 反而更高（B 0.274）。作为参照，人类同批窗口 r250 中位 0.351 / r1000 0.476。
**本轮不出谱包**，未做 Koishi 难度/可玩性评估。

## 5. 结论

1. **真的学到采音了，但只在粗粒度上。**
   B 在配对条件下的密度–强度相关 **r250 = 0.207（val）/ 0.165（test）**，
   而三个「无采音」基线分别是 A **0.080/0.019**、条件置零 **0.009/0.029**、
   给错条件后对真 C **−0.058/−0.041**。配对 − 错配 = **+0.223 / +0.166**（p=1.2e-7 / 4.8e-4，
   24胜0负 / 17胜3负）。**判定：B 学到了采音，显著高于错配基线与 A。**
2. **到什么程度**：达到人类同批谱面的 **59%（250ms，val）/ 42%（test）**、
   **30%（1000ms，val）**；去掉「密度先验」地板（A 的 0.080 / 0.019）后，音频专属成分约 **0.13 / 0.15**。
   相位锁定（峰-背景差）在 val 上接近人类的 79%，但 test 上只有 0.054 vs 0.265 —— 不稳健，不作为结论。
3. **没学到的部分**：1/32 格级的踩格相位（`p_odd_hi` 配对 = 错配，只比结构基线高 0.09，
   人类高 0.17）。相位分辨率受分支 `stride=4`（≈160ms）限制，±1 格（40ms）平移即失效。
4. **val 损失佐证但不足以定论**：B 0.0809 vs A 0.0818（−1.1%），从 epoch 4 起每轮都更低。
5. **旧集上的一切结论作废**（数据本身有系统性一格相位差，见第 1.2 节与 round149 报告）。

## 6. 剩余限制

1. **数据规模太小**：2887 窗 / 114 谱 / **25 首歌**，比旧集（5279 窗 / 40 歌）还小 45%。
   验收只覆盖 val 6 歌 + test 5 歌，**有效样本量是「歌」而不是「窗」**，
   所以结论的统计强度有限（n=24/20 窗，但只有 11 首歌）。要确认「跨曲泛化」需要更多歌。
2. **条件只有 4 带 onset**：低/中/高/总四条 1/32 格能量包络。它表达不了音色、旋律、
   鼓组位置等信息，也决定了模型最多只能学到「哪里响就哪里密」，而不是「跟着哪个声部踩」。
   换 128 带 mel（同接口，纯 CPU 可重跑）是下一档提升的主要方向。
3. **相位分辨率被结构卡住**：条件分支 `stride=4`（≈160ms）→ 40ms 级踩格不可能学到。
   若要 1/32 级对齐，需要把分支改成不打折（stride 1、通道少一些）或加残差/上采样对齐。
4. **占用偏低**：阈值 0.5 下生成占用 0.17 vs 人类 0.23；本轮的应对只是「事后校准阈值」，
   不是模型改进。真正修法是把密度目标改成占位率回归 + 采样端引导。
5. **只有 1 个种子、1 套评估窗口**：A/B 用同一 `--init-seed 7` 配对，但没有多种子重复；
   ±0.03 量级的差值不宜过度解读。`B-错配` 的 0.171 说明「条件保真」本身很强，
   后续如果用 CFG，需要在「保真 vs 对齐」之间做权衡。
6. **`p_odd_hi` 指标对数据结构敏感**：均匀基线 0.639 而不是 0.5，报告里已按「配对 vs 错配 +
   相对基线」给结论，单看绝对值会误导。

## 8. 下一步建议

1. **把条件分支改成 stride-1（或 stride-2 + 逐位置对齐）**，这是「1/32 格踩格」能不能学到的
   结构性前提；本轮的 ±1/±4 格实验已量化出当前分辨率 ≈160ms。
2. **条件换成 128 带 mel**（`tools/audio-cond-data.py` 同接口）：4 带包络的上限已到，
   想学「踩哪个声部」必须加带宽。
3. **补歌数量**（25 → 60+ 首）：采音验收的最小可信样本是歌，不是窗；当前 11 首歌撑不起
   「跨曲泛化」的强结论。
4. **训练端加密度/占用条件回归**（而不是只靠阈值 0.5），把生成占用从 0.17 拉到 0.23，
   本轮只能事后校准。
5. 若要 CFG：`--cond-drop 0.1` 已在 B 里铺好，但需先解决「保真 vs 对齐」的权衡（见 4.2 第 2 点）。
